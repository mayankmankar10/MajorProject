# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project Overview

**SmartServe** is a multi-agent, AI-powered platform designed to automate and optimize workforce recruitment, job matching, and digital onboarding in the hospitality sector. The system uses orchestrated agent flows, retrieval-augmented generation (RAG), and real-time notifications within a scalable, privacy-conscious web ecosystem.

### Tech Stack
- **Frontend**: React.js + Tailwind CSS (replacing Next.js)
- **Backend**: FastAPI + SQLAlchemy + LangChain + OpenAI function-calling API
- **LLM**: OpenAI GPT-4o for reasoning, GPT-4 Turbo for job enhancement
- **Embeddings**: OpenAI text-embedding-3-large
- **Vector Store**: ChromaDB
- **Database**: SQLite
- **Orchestration**: LangChain agent workflows
- **Real-time**: WebSockets for in-app notifications
- **Security**: Encryption at rest/transit, human-in-the-loop controls

### Core Features

- **Multi-role support**: Separate workflows for Employers and Employees
- **Automated job posting**: Job enhancement using GPT-4 Turbo
- **Intelligent matching**: Semantic vector search + rule-based filters
- **Interview scheduling**: Integrated calendar sync with in-app notifications
- **Digital onboarding**: Offer letters, NDAs, checklists generated by LLM
- **Real-time analytics**: Dashboard with operational feedback and KPI tracking
- **Human-in-the-loop**: Critical decisions require human approval
- **Privacy-by-design**: Encryption at rest/transit, secure data handling

### Key Architecture Components

#### 1. Multi-Agent Orchestration Layer (`backend/orchestration/`)

**Role**: Central controller coordinating agent flows and tool invocations

**Components**:
- **Orchestrator** (`orchestrator.py`): LangChain-based workflow orchestration
  - Manages user session data
  - Triggers appropriate tool/API calls in correct sequence
  - Ensures end-to-end automation for recruitment, matching, interview setup, onboarding
- **Agent Dispatcher** (`agent_dispatcher.py`): Routes user requests to appropriate agent
- **Workflow Definitions** (`workflows/`): Pre-defined orchestration flows for common tasks

#### 2. Connector Agents (`backend/agents/`)

**EmployerConnectorAgent**:
- Controls employer session flow after login
- Manages job posting workflow with GPT-4 enhancement
- Initiates candidate matching via MatchingTool
- Orchestrates interview scheduling
- Triggers onboarding workflows for selected candidates

**EmployeeConnectorAgent**:
- Controls employee session flow and profile setup
- Coordinates resume/CV upload and parsing
- Facilitates job discovery and application workflow
- Manages interview and onboarding status updates

#### 3. Tool Microservices Layer (`backend/tools/`)

**Core Tools** (LangChain-integrated):

| Tool | Purpose | Tech |
|------|---------|------|
| `ProfileAnalyzerTool` | Profile summarization for context | OpenAI GPT models |
| `JobPostingTool` | Employer job creation and storage | FastAPI, LangChain |
| `JobDescriptionEnhancer` | Rewrite/enhance job descriptions | GPT-4 Turbo |
| `EmbeddingGenerator` | Text-to-vector conversion | OpenAI text-embedding-3-large |
| `MatchingTool` | Vector search for candidate/job matching | ChromaDB similarity search |
| `FilterTool` | Certification & skill eligibility filters | Python rule engine |
| `ResumeParserTool` | Structured resume/CV parsing | Spacy NLP |
| `InterviewSchedulerTool` | Calendar sync & interview invitations | In-app + Calendar API |
| `NotificationTool` | In-app real-time notifications | WebSockets + Dashboard |
| `OnboardingTool` | Generate offer letters, NDAs, checklists | GPT-4 Turbo + templating |
| `ChecklistGenerator` | Onboarding task list creation | LLM |
| `JobFinderTool` | Job search engine for employees | Vector embeddings + search |
| `JobRecommenderTool` | ML-based personalized recommendations | LLM + retriever |
| `ApplicationTool` | Job application workflow management | FastAPI + database |

#### 4. Database Layer (`backend/db/`)

**SQL Database** (`sql_db.py`):
- SQLAlchemy ORM with SQLite
- Models in `models.py`

**Vector Database** (`vector_db.py`):
- ChromaDB for job descriptions & resume embeddings
- OpenAI text-embedding-3-large for semantic search

**Core Data Models**:
- `User`: Unified user with role (employer/employee)
- `Employer`: Company profile, verification status
- `Employee`: Resume, skills, experience, certifications
- `Job`: Title, description, requirements, embedding, created_by (employer_id)
- `Application`: job_id, employee_id, status, created_at
- `Interview`: application_id, scheduled_at, calendar_link, status
- `OnboardingTask`: task_id, employee_id, job_id, type (offer/nda/checklist), status
- `Notification`: recipient_id, message, action_link, read_status, created_at

#### 5. Real-time Notification System (`backend/notifications/`)

- WebSocket server for live dashboard updates
- Notification types: job matches, interview invites, onboarding updates, task reminders
- Dashboard badges and in-app notification panel
- No external email/SMS APIs—all in-app

#### 6. Chat Interface & Chatbot (`backend/chat/`)

**Embedded Chatbot**:
- OpenAI GPT-4o powered

- Contextual responses with task progress updates

**Supported Commands**:

#### 7. API Routes (`backend/routes/`)

**React.js + Tailwind CSS**:

## Implementation Workflow & Data Flow

### End-to-End Recruitment Flow

**1. Role Selection & Registration**
   - User selects role (Employer or Employee) at `/auth/role-selection`
   - Registration: `POST /api/auth/register` → User + role-specific profile created
   - Login: `POST /api/auth/login` → JWT token issued, session initialized

**2. Agent Activation**
   - Orchestrator activates appropriate ConnectorAgent based on user role
   - Agent manages session context throughout user interaction

**3. Employer Workflow (via Chat Interface)**

   a. **Job Posting**:
   - Employer: "Post a new chef job" (chat command)
   - Orchestrator → `JobPostingTool` → Job data collected
   - Orchestrator → `JobDescriptionEnhancer` (GPT-4 Turbo) → Enhanced JD
   - Orchestrator → `EmbeddingGenerator` → Vector created
   - Orchestrator → Store in SQL + ChromaDB
   - Notification sent: "Job posted successfully"

   b. **Candidate Matching**:
   - Employer: "Find top matching candidates" (auto-triggered or chat command)
   - Orchestrator → `MatchingTool`:
     - Queries ChromaDB with job embedding
     - Returns top k candidates by similarity score
     - `FilterTool` applies certification/skill filters
   - Results displayed in dashboard with match scores

   c. **Interview Scheduling**:
   - Employer selects candidates for interview
   - Orchestrator → `InterviewSchedulerTool`:
     - Calendar availability checked
     - Interview slots generated
     - Creates Interview record in database
   - `NotificationTool` → In-app notification sent to candidates

   d. **Candidate Selection & Onboarding**:
   - Employer confirms hire
   - Orchestrator → `OnboardingTool`:
     - Generates offer letter (GPT-4 Turbo)
     - Creates NDA document
     - `ChecklistGenerator` → Onboarding checklist
   - Documents stored, notifications sent
   - Employee dashboard updates with onboarding tasks

**4. Employee Workflow**

   a. **Profile Setup & Resume Upload**:
   - Employee uploads resume: `POST /api/employee/upload-resume`
   - Orchestrator → `ResumeParserTool` (Spacy NLP):
     - Extracts: skills, experience, certifications, education
     - Structured data stored in Employee model
   - Orchestrator → `EmbeddingGenerator` → Resume vector created
   - Vector stored in ChromaDB for matching

   b. **Job Discovery**:
   - Employee: "Show me job recommendations" (chat or dashboard)
   - Orchestrator → `JobRecommenderTool`:
     - Retrieves employee profile embedding
     - Queries ChromaDB for similar job embeddings
     - `FilterTool` ensures eligibility match
   - Personalized job list displayed with match scores

   c. **Job Application**:
   - Employee clicks "Apply" or chats: "Apply to this job"
   - Orchestrator → `ApplicationTool`:
     - Creates Application record (status: "applied")
     - `NotificationTool` → Employer notified of new application
   - Dashboard updated with application status

   d. **Interview & Onboarding**:
   - Employee receives interview notification
   - Accepts/declines via dashboard
   - After selection, onboarding tasks appear in dashboard
   - Downloads offer letter, signs NDA, completes checklist
   - Status updates tracked in real-time

### Orchestration Logic

**Chat-Driven Automation**:
- All employer/employee actions can be triggered via natural language chat
- Orchestrator parses intent using GPT-4o
- Maps intent to tool invocation sequence
- Manages context across multi-step workflows
- Provides progress updates via chat responses

**Example Orchestration Sequence** (Employer posts job):
```
User: "Post a senior chef position in Mumbai"
  ↓
Orchestrator receives command
  ↓
GPT-4o parses intent: job_posting
  ↓
Orchestrator invokes JobPostingTool (collect details)
  ↓
JobDescriptionEnhancer (GPT-4 Turbo enhances JD)
  ↓
EmbeddingGenerator (create vector)
  ↓
Store in SQL DB + ChromaDB
  ↓
NotificationTool (confirm to user)
  ↓
Chat response: "✅ Job posted! Would you like to find matching candidates?"
```

### Matching Algorithm

**Semantic Vector Search** (Primary):
1. Job description vectorized via OpenAI text-embedding-3-large
2. Employee resume vectorized with same model
3. ChromaDB cosine similarity search
4. Top-k candidates retrieved (default k=10)

**Rule-Based Filtering** (Secondary):
- `FilterTool` checks:
  - Required certifications present
  - Minimum experience threshold met
  - Location preferences match
  - Availability aligned

**Scoring**:
- Semantic similarity score (0-1)
- Rule compliance bonus/penalty
- Final match score displayed to employer
- Threshold: > 0.6 for "strong match" badge

**Agent Configuration**:
```python
# Orchestrator uses LangChain's AgentExecutor

```

**Tool Registration**:
- All tools in `backend/tools/` must inherit from `BaseTool`

### WebSocket Architecture

**Connection Management**:
- Each authenticated user gets a WebSocket connection
- Connection stored in `ConnectionManager` with user_id as key
- Heartbeat/ping-pong for connection health monitoring

**Notification Dispatch**:
- Tools call `NotificationTool.send()` with recipient_id and message
- NotificationTool pushes to WebSocket if user online
- Otherwise, stores in DB for later retrieval

### Security Configuration

**Authentication**:
- JWT tokens issued on login
- Token stored in localStorage (frontend)
- Authorization header: `Bearer <token>`
- Middleware validates token on protected routes

**Encryption**:
- Sensitive fields encrypted at rest using `cryptography.fernet`
- TLS/SSL for production deployments
- API keys never logged or exposed in responses

**Human-in-the-Loop**:
- Critical actions flagged with `requires_approval=True`
- Routed to approval queue in employer dashboard
- Actions: candidate selection, offer generation, interview scheduling

## Code Patterns & Best Practices

### Agent Architecture

**Connector Agents** (Stateful):
- Maintain user session context
- Store conversation history
- Manage multi-step workflows
- Example: `EmployerConnectorAgent.handle_job_posting_flow()`

**Orchestrator** (Stateless):
- Routes commands to appropriate agent
- Invokes tools in correct sequence
- Aggregates responses for chat interface
- Example: `Orchestrator.execute_command(user_id, command)`

### Tool Development

**Tool Template**:
```python
from langchain.tools import BaseTool
from typing import Optional

class YourTool(BaseTool):
    name = "your_tool_name"
    description = "Clear description for LLM to understand when to use this tool"
    
    def _run(self, param1: str, param2: Optional[int] = None) -> dict:
        """Execute tool logic and return result."""
        # Implementation
        return {"status": "success", "data": result}
    
    async def _arun(self, *args, **kwargs):
        """Async version (optional)."""
        return self._run(*args, **kwargs)
```

**Best Practices**:
- Single responsibility per tool
- Return structured data (dict/Pydantic model)
- Handle errors gracefully with try/except
- Log tool invocations for audit trail
- Include human-readable status messages

# Always use context managers or try/finally

## Testing & Debugging

### Common Issues & Solutions

**OpenAI API Errors**:
- Check `OPENAI_API_KEY` is correctly set in `.env`
- Verify API quota/billing status
- Use rate limiting for production (implement retry with backoff)
- Debug: `curl https://api.openai.com/v1/models -H "Authorization: Bearer $OPENAI_API_KEY"`

**Vector Store Issues**:
- If ChromaDB fails to initialize, check `./vectors/chroma/` permissions
- Reset vector store: `Remove-Item -Recurse vectors\chroma; python -c "from backend.db.vector_db import init_vector_store; init_vector_store()"`
- Check embedding dimensions match (text-embedding-3-large = 3072 dims)
- Verify ChromaDB version compatibility with langchain-chroma

**Database Locks** (SQLite):
- Close all DB sessions properly in try/finally blocks
- Use connection pooling: `create_engine(..., pool_size=10, max_overflow=20)`
- For production, migrate to PostgreSQL

**WebSocket Connection Issues**:
- Check CORS settings allow WebSocket origin
- Verify token is passed in connection URL: `ws://host/ws?token=xxx`
- Test connection: `wscat -c ws://localhost:8001/ws?token=your_token`
- Check `ConnectionManager` logs for disconnect reasons

**Resume Parsing Failures**:
- Ensure Spacy model installed: `python -m spacy download en_core_web_sm`
- Test directly: `python -c "from backend.tools.resume_parser import ResumeParserTool; ResumeParserTool().run('resume text')"`
- Check for non-UTF8 characters in uploaded resumes
- Fallback to regex parser if Spacy unavailable

**Orchestrator Not Invoking Tools**:
- Check tool descriptions are clear and specific
- Verify tools registered in orchestrator initialization
- Increase GPT-4o temperature (0.1-0.3) for more creative tool selection
- Debug: Log all tool invocations in orchestrator

**Chat Interface Issues**:
- Verify WebSocket connection established
- Check conversation history maintained in session
- Clear session if context becomes too long (>10k tokens)
- Test intent parsing separately from tool invocation

## Development Workflow

### Adding a New Tool

1. Create tool class in `backend/tools/your_tool.py`
2. Inherit from `BaseTool` and implement `_run()` method
3. Register in `backend/orchestration/orchestrator.py`
4. Write unit tests in `tests/test_tools.py`
5. Update tool list in WARP.md
6. Test via chat interface: "Use [tool name] to..."

### Adding a New Agent Workflow

1. Define workflow in `backend/orchestration/workflows/your_workflow.py`
2. Specify tool invocation sequence
3. Add workflow trigger to agent's command parser
4. Create integration test
5. Document workflow in this WARP.md

### Extending Database Schema

1. Add model to `backend/db/models.py`
2. Create Alembic migration: `alembic revision --autogenerate -m "description"`
3. Review migration file in `alembic/versions/`
4. Apply migration: `alembic upgrade head`
5. Update WARP.md data models section

### Adding New API Endpoint

1. Create route in appropriate `backend/routes/*.py` file
2. Use Pydantic models for request/response validation
3. Add authentication decorator if needed: `@require_auth`
4. Document endpoint in API docs (FastAPI auto-generates)
5. Write integration test in `tests/test_routes.py`
6. Update frontend API client

- **Embeddings**: Use OpenAI text-embedding-3-large (3072 dims) consistently
- **Chat Interface**: All user-facing messages should be friendly and actionable

### Agent Orchestration Guidelines

- **Context Management**: Limit conversation history to last 10 exchanges (token management)
- **Tool Selection**: Provide clear, unambiguous tool descriptions for LLM
- **Error Recovery**: Orchestrator should retry failed tool invocations (max 3 attempts)
- **Human-in-the-Loop**: Flag critical decisions; never auto-execute hiring decisions
- **Session State**: Store session data in Redis (production) or in-memory (dev)

### Testing Requirements

- **Unit Tests**: Every tool must have unit tests with >80% coverage
- **Integration Tests**: Test full workflows (job posting → matching → interview)
- **Mock External APIs**: Use pytest fixtures to mock OpenAI responses
- **WebSocket Tests**: Test connection, message delivery, and reconnection logic
- **Performance Tests**: Benchmark embedding generation and vector search

### Documentation Standards

- **Tool Descriptions**: Must be clear enough for GPT-4o to select correctly
- **API Endpoints**: Document request/response schemas in docstrings
- **Workflows**: Diagram multi-step orchestration flows
- **Configuration**: Document all environment variables with examples
- **Architecture Decisions**: Log major design choices in ADR format

### Development Principles

- **Write efficient, production-ready code** on first attempt
- **Avoid creating test files** for quick checks; use REPL or direct testing
- **Modular design**: Separate concerns (agents, tools, orchestration, routes)
- **Fail gracefully**: Vector store failures should fall back to SQL search
- **Privacy-first**: Encrypt sensitive data; log minimal PII
- **User-centric**: In-app notifications preferred over email/SMS
- **Extensible**: New tools/agents should integrate without core changes
